# Changelog

## 0.5.0 — unreleased

- Fleet in English (switch-fleet 0.9.0): the pane, the Deck, toasts, alerts, the status line, the hub tools' answers and the prompts sent to workers. Workers now answer `TASK DONE` and `HANDOVER READY`; the older `ENCARGO TERMINADO` and `RELEVO LISTO` are still read. Priorities show as high/medium/low and `fleet_open_worker` takes `high`/`medium`/`low` (the stored `alta`/`media`/`baja` still work). fleet-director's levels are `high`/`medium`/`low`, its plan table and `ask-gemini.ps1` are in English, and answers are marked `status: UNVERIFIED`.
- fleet-director skill: in a hub session it splits a request into tasks and plans who does each (the hub, a worker on another Claude account, ChatGPT through Codex, Gemini through Antigravity) with level, model, effort and priority, from a routing table (`director.default.json`, overridable in `~/.claude-switch/director.json`). The plan is shown for approval before anything starts. At a Claude cap a task goes to another provider of the same level or waits for the five-hour reset; it never moves to another Claude account. `LIMITS.md` tells the hub what each executor can and cannot do, what only the user can do, and what a brief must carry; the plan lists the user's own steps. ChatGPT and Gemini are read-only for now; `ask-gemini.ps1` runs `agy -p` in plan mode with the sandbox, blocks secret-looking prompts and saves answers as unverified. `install-skill.ps1` installs it beside switch-account.
- switch-fleet 0.8.0: `fleet_status` adds each account's plan, the weekly reset and cap, and a line per other subscription (ChatGPT, Gemini: windows, resets, reading age). The first prompt of a hub session carries a note to use fleet-director (option `director`, on by default).
- Gemini in Fleet (switch-fleet 0.7.0): a card with Antigravity's weekly limits, one per group of models (`Gemini 7d`, `Claude/GPT 7d`), from `agy -p /usage --output-format json` (a slash command: no model turn, no tokens). One session at a time asks every 10 minutes and keeps the answer in `~/.claude-switch/gemini-usage.json`; agy's log goes to one overwritten file there. A failed run keeps the last answer and says why on the card. `agyPath` option; no agy, no card. Also in the status line and the alerts.
- ChatGPT in Fleet (switch-fleet 0.6.0): a card with ChatGPT's usage windows (percent used, reset, plan) read from the newest Codex session file under `~/.codex/sessions` (`CODEX_HOME` honoured). No credentials, no network; as fresh as the last Codex turn, marked stale after 6 hours. Also in the status line (`GPT 99%`) and in the once-per-window alerts at 90 % and at the limit.
- Fleet Deck (switch-fleet 0.4.0): in the desktop app and the editor, `/fleet` draws SVG gauges per account (use, pace projection, cap tick), a lane per hub worker (phase, generation, context against the hand-over threshold, last answer) and, in hub sessions, controls to message, stop and open workers through the same checks as the `fleet_*` tools. The terminal keeps the text pane.
- switch-fleet 0.5.1: `openOnStart` also opens the pane in the desktop app and the editor (they attach after start, so it opens at the first turn); the weekly-reset match allows /usage's rounding to the minute; a worker that finished and closed its tab shows as finished with its last answer.
- Fleet Deck v2 (switch-fleet 0.5.0), laid out like Flightdeck: title and legend, account cards side by side, a task board of the hub's workers (title from the brief's first line, priority `alta`/`media`/`baja` set at open or from the card, open tasks first) and one sessions box. `fleet_open_worker` takes an optional `priority`.
- Fleet reads whose quota a session spends from its live limits (the weekly reset, fixed per account): a session of one config dir signed in with another account (the desktop app, say) gives its live use to that account and is marked `cuota de B`, instead of overwriting its config dir's account (switch-fleet 0.4.1).

## 0.4.0 — unreleased

- Hub mode in the Fleet mod (0.3.0): sessions of the hub account (`hubAccount`, default A) get the tools `fleet_status`, `fleet_open_worker`, `fleet_send` and `fleet_stop_worker`. A worker is opened on a named account (never the hub's, never `auto`, only when that account is ready) with its brief in `~/.claude-switch/workers/`. At `rolloverPercent` of context (default 40) the worker writes a hand-over and the hub opens its next generation on the same account. At a limit the worker waits for its own account's reset and then goes on by itself. Messages go through `~/.claude-switch/inbox/` and reach a worker when it is idle.
- `open-session.ps1 -WorkerName` (and `Open-ClaudeSession -WorkerName`): marks the tab as a Fleet worker (`SWITCH_FLEET_WORKER`); every other tab drops an inherited worker name.
- A worker reopened under a name used before does not get the mail left for its earlier run (`mailFrom` in the worker record), and a record written from an earlier copy keeps a `fleet_stop_worker` that landed in between.
- Hand-over hardening: a successor request is kept in the worker record (`successorDue`), so it is opened once the account is ready even after the asking tab has closed; a predecessor that comes back with a lost heartbeat never gets a second successor while the current generation runs; a worker stopped at a limit while a hand-over was owed is asked for the hand-over again when the window resets.

## 0.3.0 — unreleased

- Login state: `Get-AccountAuth` reads `claude auth status --json` (logged in, method, plan, tier, login expiry; nothing else is kept). `Get-ClaudeAccountStatus` reads it first: a logged-out account is reported as such with the command that logs it in again, instead of "no Current session line", and is not asked for `/usage`. `-List` lines add the plan and login expiry.
- `/usage` answered with the API cost summary (`Total cost:`) now says the account is not logged in with a subscription.
- Accounts are read side by side.
- `open-session.ps1 -List` writes `~/.claude-switch/status.json` (`Save-FleetSnapshot`, schema 1) and deletes session heartbeats older than a day.
- Fleet mod (`mod/switch-fleet`): a Flightdeck-style pane with every account (login, 5-hour and weekly gauges against the caps, resets) and every session on each (folder, model, current tool, context, cost), from local heartbeat files. `/fleet`, `/fleet refresh`, `/fleet close`.
- Forecast and alerts: `-List` keeps `~/.claude-switch/usage-history.jsonl` (8 days); the Fleet pane shows each window's pace and when it reaches the cap, and toasts (once across sessions) a cap within 45 minutes, a weekly cap within a day and a login that expires within 3 days.
- Pipeline in the pane: `run-pipeline.ps1` writes `~/.claude-switch/pipeline.json` after each cycle (`-StatusPath`), drawn as a PIPELINE box.
- Open from the pane: a ready account's card opens a Claude Code tab on it in the session's folder (`1`-`9`), through `open-session.ps1`, so caps and readiness still apply.
- `Get-UsageReport` and `scripts/usage-report.ps1` (also `/fleet report`): usage per account and day. The skill installer copies the script.
- This repository is a plugin marketplace (`.claude-plugin/marketplace.json`): `/plugin install switch-fleet --marketplace KBroneZ/Switch-Accounts`.
- `MOONSHOT.md`: the 12-month plan this release carries out.

## 0.2.0 — unreleased

- Usage reader: an account with no use in the 5-hour window (CLI 2.1.295 prints no `Current session` line) reads as 0% with no reset time, but only in that exact layout; any other text without the line stays unknown. Its weekly usage stays unknown.

- `Open-ClaudeSession` and `scripts/open-session.ps1`: open a Windows Terminal tab with Claude Code on one of your accounts. `-Account <name|auto>` (auto = the account with the lowest 5-hour usage that is below its caps and ready), `-Model`, `-Effort`, `-SubagentModel`, `-RemoteControl` with `-SessionName` (the name is always passed explicitly), `-InitialPrompt`, `-Title`, `-Worktree <branch>` (a git worktree under `<repo>\.claude\worktrees` from the remote's default branch), `-Count`, `-PrintOnly` / `-WhatIf`. Documented exit codes 0-5. The tab drops variables inherited from the launching session, the script travels as `-EncodedCommand`, every value is validated first, and no option can skip permission checks.
- `~/.claude-switch/accounts.json` (created with defaults, `Get-SwitchAccountConfig`, `-ShowConfig`): per account the config dir, whether Remote Control is allowed, the 5-hour cap, an optional weekly cap and the default model, effort and subagent model. No credentials.
- `Get-ClaudeAccountStatus` (`open-session.ps1 -List`): usage (5 h and weekly), caps, reset time and readiness of every account. Unknown usage means not available.
- Readiness: a session does not start when the account has not finished its first start or does not trust the folder; the error says what is missing. Only `hasCompletedOnboarding` and the folder trust marks of `.claude.json` are read. `-TrustDirectory` (explicit) marks the folder as trusted, with a backup of the file.
- `skills/switch-account` and `scripts/install-skill.ps1`: the skill (one `AskUserQuestion` for account, model, effort and Remote Control) is installed from this repository, with a backup of the previous one.
- Hardening from the code and security reviews: labels cannot start with `-`; a `claude.cmd`/`.bat` CLI is refused; `-TrustDirectory` also refuses the parents of the home folder, system folders and configured config dirs and replaces the file atomically; worktrees refuse links and Windows device names; the wrapper only accepts `-ConfigPath`/`-ClaudePath` with `SWITCH_ACCOUNTS_ALLOW_OVERRIDES=1`; a missing git is exit code 5.
- Tests: the fake CLI writes UTF-8, so the usage tests also pass when the console code page is not UTF-8.

## 0.1.0 — unreleased

- `Get-AccountUsage` and `Test-UsageCap`: 5-hour usage per account from `claude -p /usage`, fail-closed cap. The parser follows the one-line `Current session: NN% used · resets ...` layout of CLI 2.1.284, checked against real output.
- `Initialize-SecondaryAccount` and `Test-SecondaryAccount`: share rules, skills and agents with a second config dir through directory links, plus a `CLAUDE.md` import; credentials and account state untouched.
- `Get-QueueTask`: Markdown task queue with a YAML header.
- `Invoke-AccountSession`: capped `claude -p` session with turn and time limits, a per-session usage guard hook, and a kill on rate-limit rejection.
- `Invoke-PipelineCycle` and `scripts/run-pipeline.ps1`: A implements while B reviews, separate worktrees and branches, review rounds, JSON Lines run log, `-DryRun`.
- Weekly usage: `ConvertFrom-UsageText` and `Get-AccountUsage` also return `WeeklyPercent` and `WeeklyResetsAt` from the `Current week (all models)` line (`$null` when missing; the 5-hour result does not change). `Test-UsageCap -MaxWeeklyPercent` adds an optional weekly cap; without it nothing changes.
- `scripts/usage-guard.ps1`: optional `-MaxWeeklyPercent`; it reads usage again after each interval even after it has stopped a session (a resumed session can go on once the window resets), and several sessions of one account can share a state file (atomic replace, retry on a busy file).
